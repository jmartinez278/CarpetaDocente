### 1.3. Contexto local (glocal)

- La institución está en el distrito de Huayucachi (Huancayo, Junín). Solo el aula de cómputo y la dirección tienen wifi; las aulas no tienen computadora y hay cobertura 4G/5G de los operadores (integrante del equipo con experiencia en la I.E., sección 1.1). Por eso el uso principal del docente es el celular con datos móviles.
- Hay docentes con celulares de distintos sistemas operativos, por eso el sistema es web y no una aplicación nativa.
- El sistema convive con los canales oficiales: el SIAGIE, para las notas, y los medios que indique la UGEL. No los reemplaza ni se conecta con ellos.
- Los docentes adaptan sus sesiones en un procesador de textos. El sistema no ofrece un editor de sesiones: guarda, organiza y comparte los archivos.

### 1.4. Perspectiva ética

- **Datos de menores de edad:** se registran nombres, notas y asistencia de estudiantes. Se aplica la Ley N.° 29733: datos ficticios durante el desarrollo, y datos reales solo con autorización de la institución (RES-02).
- **Consentimiento del docente:** ninguna sesión entra al repositorio sin que su autor acepte, al subirla, los términos de publicación. Al aceptarlos, la sesión queda visible para todos los docentes y la dirección. El docente puede retirarla en cualquier momento eliminándola (RF-016) (RES-05).
- **Material de terceros:** solo se cargan sesiones cuyo uso esté permitido, con la fuente registrada (SUP-08).
- **Sin generación automática de contenido:** el sistema no produce sesiones ni calificaciones por sí mismo; todo lo registra o aporta una persona.

### 1.5. Decisiones del equipo que acotan los requisitos

| Decisión | Efecto en los requisitos |
|---|---|
| Las sesiones se adaptan en un procesador de textos | No hay editor de sesiones; el repositorio sube, organiza, busca y descarga archivos. |
| El equipo administra las cuentas | Hay un rol Administrador: los docentes o la dirección lo contactan y él crea el usuario. |
| La lista de estudiantes se importa | El docente la importa desde una hoja de cálculo, por ejemplo la nómina que maneja la dirección. No se incluye lectura de documentos escaneados. |
| La asistencia tiene cuatro estados | Asistió, Tarde, Faltó y Justificado. Una inasistencia o una tardanza con justificación se registra como Justificado, no como Tarde. |
| La asistencia se guarda sola | Cada toque en el círculo de un estudiante se guarda en ese momento, sin botón Guardar. Si quedan estudiantes sin estado, la jornada queda incompleta y se muestra como tal (RF-030, RNF-011). |
| La justificación es un estado más una nota corta | Justificado admite una nota opcional de hasta 100 caracteres; no se adjuntan archivos (RF-031, RN-026). |
| No se guarda el DNI de los estudiantes | Solo se registran apellidos y nombres. Un código de estudiante se agrega únicamente si el formato de la UGEL lo exige para exportar. |
| Los datos de estudiantes se conservan hasta el cierre del año escolar | Después de que la dirección descarga los consolidados, se eliminan del sistema (RF-009). |
| La matrícula no es una dimensión | El sistema no gestiona la matrícula; solo usa la lista importada. |
| Todo lo que se sube se publica | No hay sesiones privadas. Para subir una sesión, el docente acepta los términos de publicación, y desde ese momento la ven todos los docentes y la dirección. Así el repositorio no acumula archivos que nadie más puede usar. |

## 3. Especificación de requisitos funcionales

Los nombres de estudiantes y docentes de los ejemplos son ficticios.

### 3.1. Transversal: usuarios y acceso

### RF-001: Iniciar sesión

- **Dimensión:** Transversal – usuarios y acceso
- **Descripción atómica:** El sistema debe dar acceso a un usuario con una cuenta activa cuando este ingresa su usuario y su contraseña correctos.
- **Prioridad:** Alta
- **Criterios de aceptación (Gherkin / BDD):**

#### Ruta Gold (camino ideal principal)

DADO un docente con una cuenta activa
CUANDO ingresa su usuario y su contraseña correctos
ENTONCES el sistema le da acceso y le muestra la pantalla de inicio de su rol

#### Ruta Feliz (flujo alternativo válido)

DADO un usuario de la dirección con una cuenta activa
CUANDO ingresa su usuario y su contraseña correctos
ENTONCES el sistema le da acceso y le muestra el panel de consolidados

#### Ruta Infeliz (casos borde y manejo de errores)

DADO un usuario que ingresa una contraseña incorrecta, tiene la cuenta desactivada o la tiene bloqueada temporalmente por intentos fallidos (RN-024)
CUANDO intenta iniciar sesión
ENTONCES el sistema niega el acceso y muestra el mensaje "Usuario o contraseña incorrectos, o cuenta inactiva" con la indicación "Revisa tus datos. Si el problema sigue, pide ayuda al administrador.", sin indicar cuál de los datos falló ni si la cuenta está bloqueada

---

### RF-002: Cerrar sesión

- **Dimensión:** Transversal – usuarios y acceso
- **Descripción atómica:** El sistema debe terminar la sesión del usuario cuando este elige cerrar sesión.
- **Prioridad:** Alta
- **Criterios de aceptación (Gherkin / BDD):**

#### Ruta Gold (camino ideal principal)

DADO un docente con la sesión iniciada
CUANDO elige cerrar sesión
ENTONCES el sistema termina la sesión y muestra la pantalla de inicio de sesión

#### Ruta Feliz (flujo alternativo válido)

DADO un usuario con la sesión iniciada que no realiza ninguna acción durante el tiempo máximo de inactividad definido en el documento 07
CUANDO se cumple ese tiempo
ENTONCES el sistema termina la sesión automáticamente

#### Ruta Infeliz (casos borde y manejo de errores)

DADO un usuario que ya cerró sesión
CUANDO intenta volver a una pantalla interna con el botón "atrás" del navegador
ENTONCES el sistema no muestra la información y lo redirige a la pantalla de inicio de sesión

---

### RF-003: Gestionar cuentas de usuario

- **Dimensión:** Transversal – usuarios y acceso
- **Descripción atómica:** El sistema debe crear, editar o desactivar la cuenta de un docente o de la dirección cuando el administrador registra la operación.
- **Prioridad:** Alta
- **Criterios de aceptación (Gherkin / BDD):**

#### Ruta Gold (camino ideal principal)

DADO el administrador con la sesión iniciada
CUANDO registra una cuenta nueva con nombres, apellidos, usuario y rol "Docente"
ENTONCES el sistema crea la cuenta activa y muestra el mensaje "Cuenta creada"

#### Ruta Feliz (flujo alternativo válido)

DADO un docente que ya no trabaja en la institución
CUANDO el administrador desactiva su cuenta
ENTONCES el sistema impide nuevos accesos con esa cuenta y conserva los registros que el docente hizo

#### Ruta Infeliz (casos borde y manejo de errores)

DADO un usuario que ya existe en el sistema
CUANDO el administrador intenta crear otra cuenta con el mismo usuario
ENTONCES el sistema no crea la cuenta y muestra el mensaje "El usuario ya existe"

---

### RF-004: Restringir el acceso según el rol

- **Dimensión:** Transversal – usuarios y acceso
- **Descripción atómica:** El sistema debe mostrar y permitir solo las funciones y los datos que corresponden al rol del usuario cuando este solicita una pantalla o una operación.
- **Prioridad:** Alta
- **Criterios de aceptación (Gherkin / BDD):**

#### Ruta Gold (camino ideal principal)

DADO un docente asignado a "3.° grado, sección A"
CUANDO consulta las notas
ENTONCES el sistema muestra solo las notas de los estudiantes de esa sección

#### Ruta Feliz (flujo alternativo válido)

DADO un usuario de la dirección
CUANDO consulta las notas
ENTONCES el sistema muestra los consolidados de todas las secciones en modo de solo lectura

#### Ruta Infeliz (casos borde y manejo de errores)

DADO un docente asignado a "3.° grado, sección A"
CUANDO intenta abrir las notas de "4.° grado, sección B"
ENTONCES el sistema niega el acceso, muestra el mensaje "No tiene permiso para ver esta sección" y registra el intento (RF-008)

### RF-006: Importar la lista de estudiantes de una sección

- **Dimensión:** Transversal – usuarios y acceso (función de apoyo; la matrícula no es parte del alcance)
- **Descripción atómica:** El sistema debe registrar la lista de estudiantes de una sección cuando el docente importa una hoja de cálculo con la estructura de columnas indicada por el sistema.
- **Prioridad:** Alta
- **Criterios de aceptación (Gherkin / BDD):**

#### Ruta Gold (camino ideal principal)

DADO un docente con una sección asignada y sin estudiantes registrados
CUANDO importa una hoja de cálculo con 25 filas que tienen apellidos y nombres completos
ENTONCES el sistema registra los 25 estudiantes en la sección y muestra el mensaje "25 estudiantes importados"

#### Ruta Feliz (flujo alternativo válido)

DADO un docente con la lista ya importada
CUANDO agrega manualmente a un estudiante que se incorporó después
ENTONCES el sistema registra al estudiante en la sección

#### Ruta Infeliz (casos borde y manejo de errores)

DADO una hoja de cálculo con filas sin apellidos o con estudiantes repetidos
CUANDO el docente la importa

### RF-007: Restablecer la contraseña de un usuario

- **Dimensión:** Transversal – usuarios y acceso

### RF-008: Registrar la actividad de los usuarios

- **Dimensión:** Transversal – usuarios y acceso
- **Descripción atómica:** El sistema debe guardar el usuario, la fecha, la hora y el tipo de operación cuando un usuario inicia sesión, crea, modifica o elimina un registro, o intenta una operación sin permiso.
- **Prioridad:** Media
- **Criterios de aceptación (Gherkin / BDD):**

#### Ruta Gold (camino ideal principal)

DADO un docente con la sesión iniciada
CUANDO registra la asistencia de una jornada
ENTONCES el sistema guarda una entrada de actividad con su usuario, la fecha, la hora y la operación "registro de asistencia"

#### Ruta Feliz (flujo alternativo válido)

DADO el administrador
CUANDO consulta la actividad de un periodo
ENTONCES el sistema muestra el número de docentes activos por semana (con al menos un uso en la semana, KPI-01), de sesiones cargadas, de jornadas registradas y de secciones con notas registradas (KPIs del documento 03)

#### Ruta Infeliz (casos borde y manejo de errores)

DADO un docente o un usuario de la dirección
CUANDO intenta modificar o borrar una entrada del registro de actividad
ENTONCES el sistema no lo permite, porque el registro de actividad es de solo lectura para todos los roles

---

### RF-009: Cerrar el año escolar

- **Dimensión:** Transversal – usuarios y acceso
- **Descripción atómica:** El sistema debe eliminar las listas de estudiantes, las notas y la asistencia del año escolar cuando el administrador ejecuta el cierre, después de que la dirección confirma que descargó los consolidados (RF-041), según la regla de conservación del documento 09.
- **Prioridad:** Baja
- **Criterios de aceptación (Gherkin / BDD):**

#### Ruta Gold (camino ideal principal)

DADO un año escolar terminado cuyos consolidados la dirección ya descargó y confirmó
CUANDO el administrador ejecuta el cierre del año y lo confirma
ENTONCES el sistema elimina las listas de estudiantes, las notas y la asistencia de ese año, conserva las sesiones del repositorio y registra la operación en el registro de actividad (RF-008)

#### Ruta Feliz (flujo alternativo válido)

DADO un año escolar terminado
CUANDO la dirección pide conservar los datos hasta una fecha posterior
ENTONCES el administrador registra esa fecha y el sistema no permite ejecutar el cierre antes de ella

#### Ruta Infeliz (casos borde y manejo de errores)

DADO un año escolar cuyos consolidados la dirección aún no confirmó haber descargado
CUANDO el administrador intenta ejecutar el cierre
ENTONCES el sistema no elimina ningún dato y muestra el mensaje "La dirección debe descargar y confirmar los consolidados antes del cierre"

### 3.2. Dimensión 1: planificación de sesiones de aprendizaje (repositorio de sesiones)

#### Ruta Gold (camino ideal principal)

DADO un docente con la sesión iniciada

ENTONCES el sistema no genera el archivo y muestra el mensaje "No hay asistencia para exportar en ese rango"

---

### 3.5. Transversal: dirección

### RF-040: Consultar los consolidados

- **Dimensión:** Transversal – dirección (cubre D1, D2 y D3)
- **Descripción atómica:** El sistema debe mostrar, en modo de solo lectura, las notas, la asistencia y las sesiones publicadas por los docentes de cada sección cuando la dirección consulta los consolidados.
- **Prioridad:** Alta
- **Criterios de aceptación (Gherkin / BDD):**

#### Ruta Gold (camino ideal principal)

DADO un usuario de la dirección
CUANDO consulta los consolidados del periodo actual
ENTONCES el sistema muestra, por sección, los niveles de logro registrados, los totales de asistencia y las sesiones cargadas por cada docente, que la dirección puede abrir y descargar

#### Ruta Feliz (flujo alternativo válido)

DADO un usuario de la dirección
CUANDO filtra por una sola sección
ENTONCES el sistema muestra el detalle de notas y asistencia de esa sección

#### Ruta Infeliz (casos borde y manejo de errores)

DADO un usuario de la dirección que consulta los consolidados
CUANDO intenta modificar una nota o una asistencia
ENTONCES el sistema no lo permite, porque el panel de la dirección es de solo lectura

---

### RF-041: Descargar los consolidados en el formato de la dirección

- **Dimensión:** Transversal – dirección (cubre D2 y D3)
- **Descripción atómica:** El sistema debe generar un archivo con las notas o la asistencia de una o varias secciones en el formato que usa la dirección cuando esta elige descargarlas.
- **Prioridad:** Media (el formato depende de SUP-13 del documento 04)
- **Criterios de aceptación (Gherkin / BDD):**

#### Ruta Gold (camino ideal principal)

DADO un formato de la dirección configurado en el sistema
CUANDO la dirección descarga las notas del periodo de todas las secciones
ENTONCES el sistema genera un archivo con ese formato y las notas de cada sección

#### Ruta Feliz (flujo alternativo válido)

DADO que la dirección aún no entregó su formato propio
CUANDO descarga los consolidados
ENTONCES el sistema genera una hoja de cálculo con la misma estructura de RF-024 y RF-034

#### Ruta Infeliz (casos borde y manejo de errores)

DADO secciones que aún no entregaron sus notas del periodo
CUANDO la dirección descarga los consolidados
ENTONCES el sistema genera el archivo e indica qué secciones tienen las notas pendientes de entrega

---

### RF-042: Ver el estado de entrega por docente

- **Dimensión:** Transversal – dirección (cubre D2)
- **Descripción atómica:** El sistema debe mostrar, por docente y por periodo, si las notas están entregadas y en qué fecha, cuando la dirección consulta el estado de entrega.
- **Prioridad:** Media
- **Criterios de aceptación (Gherkin / BDD):**

#### Ruta Gold (camino ideal principal)

DADO docentes que marcaron sus notas como entregadas (RF-026)
CUANDO la dirección consulta el estado de entrega del periodo
ENTONCES el sistema lista a cada docente con su estado ("Entregado" o "Pendiente") y la fecha de entrega

#### Ruta Feliz (flujo alternativo válido)

DADO un docente con las notas entregadas que necesita corregir una nota
CUANDO la dirección habilita la corrección desde esta pantalla
ENTONCES el sistema cambia el estado a "En corrección" y permite al docente editar (RF-026)

#### Ruta Infeliz (casos borde y manejo de errores)

DADO un periodo que aún no ha comenzado
CUANDO la dirección consulta su estado de entrega
ENTONCES el sistema muestra el mensaje "El periodo aún no ha comenzado"
